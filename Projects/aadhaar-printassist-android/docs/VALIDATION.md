# Supported validation policy

`PdfSession` preserves the selected bytes, uses strict parsing first, and discovers PDF signature dictionaries and widget appearances. Compatibility fallback permits preview but not an overall verified result. Embedded DSS certificates are intermediate candidates only. DSS records have per-record and aggregate size limits.

`CmsVerifier` requires a four-element ByteRange starting at zero and an unsigned gap equal to the exact PDF Contents hexadecimal string. It checks supported subfilters, one CMS signer, SHA-2 content digests, signer-certificate selection, ESS certificate binding where present/required, and the signature over the selected original bytes. Only a signature covering the complete file can reach green. Later revisions are reported as unassessed; they are not automatically called malicious.

`PkiValidator` builds a PKIX path to explicit roots. Certificate validity, critical extensions/path constraints, SHA-2 policy and RSA/EC key sizes are enforced. Every non-root chain certificate requires fresh authenticated revocation evidence. Roots are trust anchors and are not checked against self-issued revocation records.

CRLs require issuer matching, issuer CRL-signing authorization, a verified signature, applicable thisUpdate/nextUpdate and supported full-CRL scope. Delta, indirect and partitioned CRLs are not accepted as complete evidence. OCSP requires the matching issuer/serial, response signature, responder-ID binding, freshness, supported critical extensions and an authorized issuer or delegated responder. A delegated responder needs the OCSP-signing EKU, a valid path to that issuer, and revocation evidence or a valid OCSP no-check extension. Revoked evidence takes precedence over good evidence at the evaluated time.

Historical mode is attempted when current-time validation is insufficient. It verifies an RFC 3161 signature timestamp's imprint, TSA signature/certificate binding and timestamping authorization. The TSA must be trusted and unrevoked now. The signer chain and revocation evidence are then evaluated at the authenticated timestamp time. Untrusted PDF/CMS dates cannot set the clock. Expired TSA/LTA preservation chains and document timestamps are not supported; absence of sufficient evidence gives INDETERMINATE.

PDF appearance is independent of cryptographic status. PDFBox reports Rect/AP/N/BBox/Matrix. Since version 0.2.1, rendering retains signature widgets only after overall verification passes. Otherwise the same annotation filter omits them from preview, PNG/JPG, native printing and print-PDF export, without covering underlying content. Flattened page artwork cannot be identified as a removable widget. The app does not insert, replace or claim an Adobe-generated tick. A visible tick in an unsigned PDF is ordinary page artwork. A print PDF is a rendered copy with no original cryptographic signature; the exact-original export remains byte-identical.

This bounded implementation is not a full PAdES conformance engine or a defense certified against all PDF shadow/signature-wrapping attacks. Additional adversarial parser and semantic-revision testing is a production release requirement. Unsupported or uncertain cases fail closed to an indeterminate result.
