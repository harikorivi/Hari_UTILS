# Privacy and security — development scope

The app processes the user-selected PDF locally and has no INTERNET, storage, camera, contacts or analytics permission. It uses a temporary Storage Access Framework grant and does not persist that grant. It never stores passwords, names or document contents in preferences, a database or files. Its own code logs no document contents. No customer PDF is included in the project or APK.

The selected original bytes and decoded page necessarily exist in process memory while open. Name/year/password fields clear after submission and when leaving the screen. The preview clears on backgrounding except while system save/print/evidence dialogs are active (rotation can retain the ViewModel). Public administrator verification evidence is the only application-persisted input; it is stored privately and excluded from backups. User-approved exports and system print jobs persist outside the app until their owners remove them. Work runs serially; clearing during a parse invalidates its eventual result and queues resource cleanup. No document temporary files are created. Abrupt process termination releases process memory. Managed-runtime/library copies and keyboard software cannot be guaranteed securely erased. The app does not delete the user's original file.

Screenshots/recents capture are restricted with FLAG_SECURE. Backup is disabled and extraction rules exclude private data. Instrumentation captures only an empty home screen for documentation and temporarily clears that flag inside test code; the production activity does not. A cloud document provider selected through the OS picker may download its own file; this is outside the app's local processing boundary.

20 MB input, 100 pages, two-million-pixel previews, eight-million-pixel exports and ten-page print jobs constrain common workloads, but PDF parsing can still consume substantial CPU/memory. This is not yet an isolated-process hardened parser. Malformed-file fuzzing, hard timeouts, library logging audit, dependency updates and physical 2 GB-device profiling remain release gates. PDFBox is an older Android port and must not be advertised as currently security-qualified merely because this prototype works. No Aadhaar QR authentication or identity matching is performed.

## Legal/product review for deployment

This app is independent software and makes no UIDAI affiliation or authentication claim. Require permission for handling the customer's document, explain purpose, minimize collection and avoid unrelated sharing. Export/printing requires clear user action and state that print/image copies lack the original cryptographic signature.

Review the current [UIDAI notice/consent guidance](https://uidai.gov.in/images/resource/Final_Aadhaar_Notice_and_Consent_Guidelines.pdf), applicable [UIDAI sharing regulations](https://uidai.gov.in/images/6_The_Aadhaar_Sharing_of_Information_Regulations_2016.pdf), and [MeitY DPDP Rules publications](https://www.meity.gov.in/documents/act-and-policies/digital-personal-data-protection-rules-2025-gDOxUjMtQWa?pageTitle=Digit) against the actual operator role, rollout date, purposes and data flows. Rules specific to authentication entities should not automatically be assumed to apply identically to an offline print shop. This engineering prototype does not establish legal compliance; effective provisions and operator obligations need deployment-specific review.
